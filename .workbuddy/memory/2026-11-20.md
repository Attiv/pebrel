## 经验

- 上游发版 tag 常常落在 `release/*` 分支上而不是 `main`：合并 main 后仍要
  `gh release list -R Kuddev/pebrel` 与 `git branch -r --contains <tag>` 确认版本口径。
- macOS 的 `sed -i ''` 在本机 zsh 下连用时会把表达式当文件名（本次报
  `sed: s/version = ...: No such file or directory`），批量替换改用 `perl -pi -e` 更稳。
- 合并中“两侧各自新增同名函数”比内容冲突更隐蔽：`git merge-tree` 预览只能看到
  文件名，处理时要读 `||||||| base` 段是否为空来判断是新增还是修改。
- README 补条目后可用脚本按小节统计 `^- ` 数量，确认中英条目数一一对应。

## 三次红的原因（都在版本对齐这一步）

1. run `44724908852`：`cargo fetch --locked` 报
   `failed to select a version for async-io = "^2.1.0"` —— 我的
   `perl -pi -e 's/version = "2.6.0"/version = "2.6.1"/g' Cargo.lock`
   把第三方 `async-io` 也抬到不存在的 2.6.1。修法：先从 `HEAD^` 恢复锁文件，
   再用正则**按包名白名单**只提升工作区包（pebrel/pebrel-*/pebrel_*），
   最后 `diff upstream/main:Cargo.lock Cargo.lock` 应只剩 7 行工作区版本差异。
2. run `44725826614`：原生测试编译失败 `E0061`，`activity_tests.rs:558` 调
   `apply_activity_evidence` 少传上游新增的 `input_lease`。fork 独有测试调用上游
   改签名的函数时不会产生 merge 冲突，只能靠 CI 编译暴露。
3. 两个平台的日志都是同一个 `E0061`，确认只有一处后一次修掉。

### 经验（重要）

- **锁文件批量替换必须按包名白名单**，绝不能全文件替换版本字符串：
  `async-io`/`futures-lite`/`subtle`/`tokio-macros` 都可能正好是 2.6.x。
- 合并后除了 `cargo fmt`，还要扫一遍**上游改签名的函数在 fork 独有测试里的调用**：
  `git diff <base>..upstream/main -- '*.rs' | grep '^-.*pub.*fn '` 对照
  `git grep "<fn>("` 的调用点数量，能提前发现这类缺参数的调用。
