## 经验

- 上游发版 tag 常常落在 `release/*` 分支上而不是 `main`：合并 main 后仍要
  `gh release list -R Kuddev/pebrel` 与 `git branch -r --contains <tag>` 确认版本口径。
- macOS 的 `sed -i ''` 在本机 zsh 下连用时会把表达式当文件名（本次报
  `sed: s/version = ...: No such file or directory`），批量替换改用 `perl -pi -e` 更稳。
- 合并中“两侧各自新增同名函数”比内容冲突更隐蔽：`git merge-tree` 预览只能看到
  文件名，处理时要读 `||||||| base` 段是否为空来判断是新增还是修改。
- README 补条目后可用脚本按小节统计 `^- ` 数量，确认中英条目数一一对应。
