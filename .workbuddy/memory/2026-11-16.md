## 第三次修正：SSH 阶段通道类型（`dc1f1d4e`）

- run `43808017692` 打包与原生测试全红，唯一根因是 4 个 `E0308`：
  `gpui_shell/terminal/session.rs` 的 `EventProxy::channel` 返回类型用了上游的
  `UnboundedReceiver<SshStage>`，而 fork 的 stage 通道实际载的是
  `SshEvent`（`SshEvent::Stage` 包装，另有 fork 独有的 `SshEvent::ForwardWarning`）。
- 上游把 stage 通道直接改成 `SshStage`，但 `ForwardWarning` 是 fork 独有，
  合并应保持 fork 的 `SshEvent` 通道：只把 `channel` 签名改回 `SshEvent`。
  `session_pump::attach`、`SpawnedSession`、`runtime.rs`、`ssh_panes.rs` 本来就是 `SshEvent`。
- 重新触发 run `43810603409`（head `dc1f1d4e`）。

### 经验
- `rustc` 报 “due to 4 previous errors” 时，等于该 crate 的类型检查已跑完，
  修完这 4 处通常就干净；可据此判断不必再猜更多。
- 合并“上游改签名 + fork 独有事件变体”时，以上游结构为准会丢掉 fork 语义，
  应以 fork 的通道类型为准，只吸收上游的无关改动。
