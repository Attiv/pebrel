## Cmd+Shift+Enter 无 AI 请求：根因（只读代码排查，未编译）

- 命令 AI 搜索被 `ai_search.rs:65 ai_search_identity()` 的
  `ssh_destination.is_some()` / `runtime_agent().is_some()` 守卫直接拒绝；
  `toggle_ai_search()` (`ai_search.rs:105`) 另有 `ALT_SCREEN | VI` 全屏守卫。
- 拦截发生在 `ai_commands::prepare()` 与 `ureq::post(url)` 之前，请求体/URL
  从未生成，故与服务商地址无关：`127.0.0.1:8045` 与 `api.openai.com` 都发不出去。
  请求由本机 Pebrel 进程用 ureq 发出，不经 SSH 隧道；loopback 还会绕过系统代理
  (`ai_inference.rs` 的 `LOCAL_CLIENT`)。本地中转 8045 实测 `/v1/models` 200。
- 设计原因：需要本地 shell integration 提供输入行/cwd/提示符状态，远端 shell
  读不到；`runtime.rs:1441 local_context_refusal()` 同样禁止把本地上下文送往远端。
- `ai_prediction.rs` 复用同一 `ai_search_identity()`，SSH 下同样静默不发请求；
  `prompt_suggestions`（本机 runtime_api，CLI hook 触发）是独立路径、无 ssh 判定；
  `ai_assistant.rs` 的错误修复请求默认 api.openai.com，但触发点在 `event.rs`，
  仅 `legacy-shell` feature 编译，正式包（gpui-shell）不触发。

## 补充现象与修正：切到本地标签仍失败，关掉 SSH 才恢复

- 用户实测：开着 SSH 时切到其它本地标签也发不出 AI 请求，关掉 SSH 即可。
  上一条 per-pane 守卫（`ssh_destination`）解释不了这种跨标签的全局性，需修正。
- 找到唯一的进程级共享资源：`ai_inference.rs:32 ACTIVE` 全局并发槽（上限 2），
  `Slot::acquire()` 失败即 `Failure::Busy`，发生在 `ureq::post()` 之前，
  因此中转看不到任何请求。命令 AI 与 `prompt_suggestions` 共用该槽：
  `service.rs:137 predict()` → `client.rs:47 request()` → `ai_inference::request()`。
  用户配置 `prompt_suggestions_enabled=1`、`ai_hooks_codex=1`、`ai_hooks_opencode=1`，
  且预测与命令 AI 同为 `custom-3`；SSH 会话里跑 AI CLI 时 hook 持续发预测请求，
  每个最多占槽 5s（`timeout_global`），可挤掉命令 AI。
- 另一候选：`render.rs:179` 快捷键分发到 `tabs[active].focused_view()`，
  若焦点仍落在 SSH pane，则命中 per-pane `search_unavailable` 守卫。
- 区分方式：看提示是 `search_busy`（"上一条 AI 请求仍在结束中"）还是
  `search_unavailable`（"…暂不支持 WSL、SSH 和前台程序"）。
  快速验证：开着 SSH 时临时关掉提示词建议再按快捷键，若恢复即为槽竞争。
- 与服务商地址无关：两种 URL 都在 `Slot::acquire()` 之后才被使用。
- 2 槽是正式契约而非随手常量：`.trellis/spec/nebula/backend/command-ai.md:32`
  （two process-wide inference slots + 5s deadline + 64 KiB + 无重定向/重试）、
  `architecture/notes/nebula_app/prompt_suggestions/2026-10-29-native-runtime-predictions.md:59`、
  `ai_inference/tests.rs:102` 的正反测试。理由：阻塞 HTTP 不可立即 abort
  （`2026-11-06-native-command-ai-ownership.md` 明写取消只抑制发布、槽留到超时），
  需给付费请求设可预测上界。spec 的 "drain explicit search first" 只在
  `ai_prediction.rs` 的 per-pane `ai_search_job` 队列生效，管不到跨能力的
  `prompt_suggestions` 抢槽 —— 这是问题的结构性来源。
- 该 note 的 "Revisit when measured slot contention" 条款已命中；
  修订需改 spec 数字 + 写单独审查过的契约 note + 补正反测试，且本地不可编译。
